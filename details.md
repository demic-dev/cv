I was the primary builder of the AI prototype for V2: an end-to-end scraping → OCR → structured extraction → RAG pipeline targeting the unstructured, inconsistently formatted PDFs that Italian public institutions publish (determine, delibere, albo pretorio postings). - **Fictional Journey** (personal project, still private but soon open sourced) - July/August 2026: I wanted to perform a data analysis of my own friends group chat, in order to get fun insights to share with the group. Since the messages are private, I set the constraint that nothing could leave my control: everything was ran on open source models, deployed by me on ephemeral hosts through VastAI (RTX 4090 and similar GPUs), so no chat content was ever sent to a third party API. The dataset was around 350k messages from 20 participants over 5 years of history, a chat I am part of, and the results were presented back to the group in an informal PowerPoint.
I built a pipeline which would export the chats through whatsapp-chat-exporter, then chunk the chat in conversations/threads/sessions (using mostly time-gap heuristics and a reply graph, which produced more than 16k chunks) and build a database out of it: both vectorial (ChromaDB) and relational (SQLite). The relational, beside keeping the metadata, kept also the normalised version of the chats, later used for simple NLP tasks. The vectorial database was used to create a RAG system, where a LLM could be queried about. The query phase implemented a router which would classify each request and then dispatch to the assigned agent. Everything was written in Python, and both the RAG and the router logic were hand-rolled, without LangChain or LlamaIndex. Ollama APIs were used, with Qwen models both for the embeddings and for the LLM. Also, the LLM was used for two other kind of classifications: the first, was to classify, given a batch of messages for each participant, the messaging style and recurring topics, to build fun "personas" for the group. The other, starting from the original normalised text, to correctly classify candidate messages which respect a predicate (eg. who's most late? In order to verify that, given chats, I would look for messages which respect certain predicates and then the LLM would classify it). Both of these labelling steps were batched, to keep the GPU busy and reduce the cost. The labels were then used to do aggregations on the relational database.
The hosts were provisioned with Docker images plus simple bash scripts, which installed Tailscale and pulled the Ollama models; I also tried to build a Nix image, to be coherent with my pc configuration, but I couldn't make it work and I fell back to the bash scripts. The whole project cost me around 10 euro of GPU spend.
It was a solo project, done in around two weeks. I checked the quality of the classifications by hand, but I didn't build a proper evaluation set, and there are no tests or CI yet. Only the infrastructure will be open sourced, never the data or the exports.
